# 팀·기술 스택: 불충분한 예 vs 충분한 예

## 팀 (`06-team.md`)

| | 불충분 | 충분 |
|---|---|---|
| 역할 | "개발자 2명, 디자이너 1명" | 역할마다 FTE, 담당 마일스톤, 채용 우선순위가 있다 |
| 예 | `백엔드 개발자｜2｜-｜-` | `크롤러·추출 개발｜0.5｜MS0, MS1｜보유｜본인. 주 20시간` |
| 채용 | "필요하면 뽑는다" | `QA·도메인 검수｜0.2｜MS2｜1｜MS1 통과 직후, 추출 정확도 상시 확인` |
| Pivot | "상황에 따라 논의" | "누가(대표 1인), 어떤 데이터(MS1 종료 조건 수치)를 보고, 언제까지(종료 후 3일) 정한다. 미달이면 P1 을 실행한다" |

체크: 모든 역할이 최소 하나의 MS# 를 맡는가 / FTE 합이 현실적인가 / 채용 순서에 이유가 있는가 / Pivot 을 누가 결정하는지 한 사람이 정해져 있는가.

## 기술 스택 (`07-tech-stack.md`)

계층마다 **선택 · 근거 · 대안 · 월 비용 · 전환 조건** 이 모두 있어야 한다.

| 계층 | 선택 | 근거 | 대안 | 월 비용 | 전환 조건 |
|---|---|---|---|---|---|
| 불충분 | "React" | "많이 쓰니까" | - | - | - |
| 충분 | 정적 HTML + GitHub Pages | MS0~MS1 은 화면이 1장이라 서버가 필요 없다 | Next.js on Vercel | 0원 | 로그인이 필요한 MS2 시작 시, 또는 월 방문 1만 회 초과 시 |

체크: 근거가 "이 프로젝트의 현재 단계" 와 연결되는가 / 대안을 실제로 비교했는가 / 비용을 숫자로 썼는가(무료는 0원) / 언제 바꿀지 숫자 기준이 있는가.

## MVP 와 마일스톤

- MVP 는 유형(Wizard of Oz, Concierge 등)을 고르고, **In 의 모든 항목이 어떤 가설을 검증하는지** 쓴다. 검증할 가설이 없는 기능은 Out 이다.
- 마일스톤은 기능 묶음이 아니라 **검증 단위**다. 각각 검증 가설, 숫자 종료 조건, No-Go 시 Pivot 옵션이 있다.

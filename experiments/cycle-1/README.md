# experiments/cycle-1 — BML Cycle 1 (H2 마감일 추출 정확도, E1)

| 항목 | 내용 |
|---|---|
| 가설 | H2 — 마감일을 규칙 기반 추출만으로 90% 이상 맞춘다 (`docs/prd/01-problem-and-hypotheses.md`) |
| 지표 | M3 마감일 추출 정확도 (`docs/prd/05-metrics.md`) |
| 사전 임계값 | 통과 ≥ 90% / 미만이면 P1 (측정 전에 고정: 커밋 `75fc283`, 측정 결과 커밋 `1d61656`) |
| 결과 | **16/19 = 84.2%** (Wilson 95% 신뢰구간 62~95%) → 기준 미달 → Pivot (P1) |
| 로그 | `docs/prd/11-bml-log.md` Cycle 1 |

## 파일

- `corpus.json` — 공개 학교 게시판·채용 공지 19건에서 마감일이 적힌 줄만 발췌, 정답은 사람이 원문을 읽고 붙임. 출처 URL 포함
- `run_eval.py` — 추출기(`noticatch/deadlines.py`)로 돌려 정답과 대조, `results.json`/`results.md` 생성
- `results.md` — 사례별 판정과 틀린 3건의 원인

재현: `python3 experiments/cycle-1/run_eval.py`

## 이 증빙의 한계 (과제 Part C 기준)

- **실제 사용자 5명 이상의 반응 데이터가 아니다.** 사용자 없이 실제 공개 공지로 추출기만 평가한 Offline evaluation이다. 과제의 "실제 사용자 5명 이상 / 가상 데이터는 명시" 기준에서 이 데이터는 사용자 데이터가 아니라 *공개 자료*이며, 정성 데이터는 틀린 사례의 원인 분석뿐이다
- 정답 라벨은 한 사람(AI 초안 작성자)이 붙였다. 라벨 오류를 다른 사람이 교차 검토하지 않았다
- 표본 19건은 서울권 대학 위주이고 공지 전체가 아니라 마감일 줄만 잘랐다 (실제 서비스보다 쉬운 조건)
- 가장 위험한 가설 두 개(H1 수요, H2 정확도)가 동점이었고, 사용자 없이 하루에 가능한 H2를 먼저 했다. H1은 아직 검증하지 않았다

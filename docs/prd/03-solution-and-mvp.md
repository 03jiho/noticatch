# 03. 솔루션과 MVP

| 제품 | 버전 | 최종 수정 | 관련 가설 |
|---|---|---|---|
| NotiCatch | 0.1 | 2026-11-26 | H1, H2, H3, H5 |

## 1. 솔루션 개요

- 고유 가치 제안: 여러 학교 게시판의 공지 중 내가 고른 키워드의 공지만, 마감일과 함께 내 캘린더에 넣어 준다.
- 핵심 사용 흐름: 키워드 1~3개 선택 → 구독 링크(`.ics`) 발급 → 캘린더 앱에 추가 → 새 공지의 마감일이 일정으로 들어옴 → D-3, D-1에 알림
- 현재 대안 대비 차이: 전체 공지를 푸시하지 않고 내가 고른 것만, 날짜를 사람이 옮기지 않고 캘린더로 준다.

## 2. MVP 유형과 선택 이유

- 유형: **Concierge** (사람이 직접 서비스하고 고객도 안다)
- 이유:
  1. 가장 위험한 가설(H2 마감일 추출 정확도, H1 수요)은 완전 자동화가 없어도 검증된다. 추출 결과를 사람이 한 번 검수해 전달하면 "캘린더로 받는 가치"와 "추출을 믿어도 되는가"를 동시에 볼 수 있다.
  2. 구축이 5~6일이고 서버·회원가입 비용이 0원이다.
  3. 코드 없는 대안(Landing page + 대기 명단)도 검토했다. H1 단독 검증에는 충분하지만 H2(정확도)를 못 재서 기각했다. 랜딩 페이지는 MS1에서 구독 링크 클릭률(M2) 측정용으로 함께 쓴다.
- 마일스톤별 MVP 진화: MS0 Offline evaluation(공개 공지로 추출기만 평가, 사용자 없음) → MS1 Concierge → MS2 Single-feature(구독 화면) → MS3 Single-feature + 리마인드

## 3. MVP 범위 (In / Out)

| 기능 | In/Out | 검증 가설 | 비고 |
|---|---|---|---|
| 게시판 2곳 공지 수집 | In | H2 | 추출 정확도를 재려면 실제 공지가 필요함 |
| 키워드·제외 키워드 매칭 | In | H5 | 첫 구독이 3분 안에 끝나는지 확인 |
| 마감일 후보 추출 | In | H2 | 가장 위험한 가설. 정확도를 숫자로 확인. Cycle 1 이후: 단정하지 않고 후보로 취급(P1) |
| 후보 날짜·원문 병기 표시 | In | H2 | P1 실행(Cycle 1): 추출이 틀려도 사용자가 원문으로 걸러낼 수 있게 한다 |
| `.ics` 캘린더 구독 링크 | In | H1 | 사람들이 캘린더로 받고 싶어 하는지 확인 |
| D-3, D-1 리마인드 | In | H3 | 리마인드가 신청 행동을 늘리는지 확인 |
| 구독 이벤트 기록 | In | — | 측정 장치 (구독 클릭·완료·캘린더 추가) |
| 이메일 알림 발송 | Out | — | `.ics` 링크로 H1을 먼저 검증할 수 있고 서버 비용이 없다. 구독자 20명 이상일 때 재검토 |
| 웹 푸시 알림 | Out | — | 어떤 가설도 검증하지 않음. H3 통과 후 재검토 |
| 회원가입·로그인 | Out | — | 처음 10명은 링크 하나로 충분. 구독자 100명 초과 시 재검토 |
| 게시판 5곳 이상 확장 | Out | — | 추출 정확도(H2) 통과 전에는 의미 없음. MS1 통과 후 재검토 |

구축 기간 추정 (1인): 8일 — 상한 10 영업일 (Cycle 1에서 후보·원문 병기 표시 추가로 6일에서 늘어남)

## 4. MVP 성공 기준

`05-metrics.md` 목표치 인용:

- M3 마감일 추출 정확도 ≥ 90% (공개 공지 마감일 줄 15건 이상)
- M1 최근 한 학기 마감을 놓친 경험이 있는 재학생 비율 ≥ 40% (인터뷰 10명 중 4명 이상)
- M2 랜딩 페이지 구독 링크 클릭률 ≥ 30% (방문 100회 이상)

실패로 간주: M3 < 90% → `10-risks-and-pivot.md` P1, M1 < 40% 또는 M2 < 30% → P2

# 05. 지표

| 제품 | 버전 | 최종 수정 | 관련 가설 |
|---|---|---|---|
| NotiCatch | 0.1 | 2026-11-26 | H1~H5 |

## 1. North Star Metric

- NSM: **마감 전에 신청을 완료했다고 답한 구독자의 비율** — 정의: (마감 전 신청 완료 응답 구독자 수) / (설문에 응답한 구독자 수), 월 1회 설문
- 왜 이 지표인가: 제품의 약속("마감을 놓치지 않는다")을 그대로 잰다. 구독자 수나 알림 수는 이 약속과 무관하게 늘 수 있다.
- 현재: 측정 전 → MS3 목표: 60% 이상 (근거: 임의값, MS1 결과로 보정 예정)

## 2. AARRR 지표

| ID | 단계 | 지표 | 정의 (계산식) | 기준값 | 목표 (MVP) | 목표 근거 | 검증 가설 |
|---|---|---|---|---|---|---|---|
| M1 | Acquisition | 최근 한 학기 마감을 놓친 경험이 있는 재학생 비율 | 인터뷰 10명 중 "최근 한 학기에 공지를 늦게 봐서 놓친 마감이 있다"고 답한 사람 / 10 | 측정 전 | 40% 이상 (4명 이상) | 임의값 — 과반에 못 미쳐도 4명이면 첫 10명 규모에서 반복 확인 가능한 수준. MS1 후 보정 | H1 |
| M2 | Acquisition | 랜딩 페이지 구독 링크 클릭률 | `subscribe_click` 사용자 수 / `landing_view` 사용자 수 (방문 100회 이상) | 측정 전 | 30% 이상 | 임의값 — 벤치마크는 확인하지 못했고 학과 단톡방 직접 공유라 일반 광고 유입보다 높을 것이라는 가정. MS1 후 보정 | H1 |
| M3 | Activation | 마감일 추출 정확도 | 마감일이 적힌 공지 줄 15건 이상에 사람이 정답을 달고 추출 결과와 일치한 건수 / 전체 | 측정 전 | 90% 이상 | 임의값 — 사용자가 캘린더를 믿고 쓰려면 10건 중 1건 이하만 틀려야 한다는 가정. 가드레일(오탐 5%)과 함께 사이클 후 보정 | H2 |
| M4 | Activation | 첫 구독 완료율과 소요 시간 | 처음 방문 5명 중 `subscribe_complete` 도달 비율, 소요 초의 중앙값 | 측정 전 | 완료율 50% 이상, 중앙 180초 이하 | 임의값 — 설정 항목이 3개 이하라는 설계 전제. MS2 후 보정 | H5 |
| M5 | Retention | 리마인드 수신자와 비수신자의 신청 완료 보고율 차이 | 20명을 두 그룹으로 나누고 14일 뒤 설문 → (수신 그룹 비율) − (비수신 그룹 비율) | 측정 전 | +10%p 이상 | 임의값 — 효과가 체감되려면 최소 한 자릿수 이상이어야 한다는 가정. 표본 20명이라 방향 확인용 | H3 |
| M6 | Referral | 구독자 1명당 초대로 추가된 구독자 수 | 구독자 링크 유입(유입 채널=공유)으로 `subscribe_complete`한 사람 수 / 기존 구독자 수 | 측정 전 | 0.3명 이상 | 임의값 — 성장 엔진의 최소선(K-factor 0.3, `mvp-and-milestone-guide.md` §2.2 전형값) | H4 |
| M7 | Revenue | 월 결제 의향 | 설문에서 월 1,000원 이상 지불 의향을 밝힌 구독자 수 | 측정 전 | 측정만 | 가설 없음 — 가치 가설 통과 전에는 가격을 검증하지 않는다 | — |

## 3. Actionable vs Vanity

| 보지 않을 숫자 (Vanity) | 이유 | 대신 볼 것 |
|---|---|---|
| 누적 구독자 수 | 해지·휴면이 포함되고 행동을 바꾸지 못한다 | M4 (첫 구독 완료율), NSM |
| 랜딩 페이지 방문 수(PV) | 관심이 아니라 노출이다 | M2 (클릭률) |
| 수집한 공지 건수 | 많이 모아도 마감일이 틀리면 해롭다 | M3 (추출 정확도) |
| 발송한 알림 수 | 많을수록 알림 피로 | M5 (신청 완료 차이), 가드레일 |

가드레일(좋아져도 나빠지면 안 되는 지표): 잘못된 마감일이 알림으로 나간 비율 5% 이하, 사용자당 주간 알림 5건 이하, 구독 해지 비율 30% 이하.

## 4. 측정 방법과 이벤트

- 도구: GitHub 저장소의 이벤트 로그(CSV)와 스프레드시트 — 선택 이유: MS1까지 사용자가 10~20명이라 PostHog 같은 별도 도구가 과하고, 이미 있는 GitHub Actions로 일일 집계가 가능하다.
- 수집 주기: 일 1회 GitHub Actions

| 이벤트 이름 | 지표 | 발생 시점 | 속성 |
|---|---|---|---|
| `landing_view` | M2 | 랜딩 페이지 진입 | 유입 채널 |
| `subscribe_click` | M2 | 구독 링크 버튼 클릭 | 유입 채널 |
| `subscribe_complete` | M4, M6 | 구독 링크 발급 완료 | 키워드 수, 소요 초 |
| `ics_added` | M2 | 캘린더 피드가 처음 조회됨 | 캘린더 앱 종류 |
| `reminder_sent` | M5 | D-3 또는 D-1 알림 발송 | 단계(D3/D1) |
| `deadline_corrected` | M3 | 검수에서 추출 마감일을 고침 | 공지 ID |

코호트 기준: 구독 주차 · 리텐션 창: D7 (MS3부터 사용)

출처: 목표치는 모두 임의값이며 근거 열에 이유를 적었다. 벤치마크 수치는 아직 확인하지 않았다("확인 필요").

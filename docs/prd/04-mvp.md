# 04. MVP

## MVP 유형

**Concierge MVP.** 크롤러가 모은 공지와 추출된 마감일을, 처음 10명에게는 사람이 한 번 검수한 뒤 `.ics` 구독 링크로 전달한다. 자동화(회원가입, 알림 서버)를 만들기 전에 "마감일을 캘린더로 받는 것"이 가치가 있는지, 그리고 마감일 추출을 믿어도 되는지를 검증하는 것이 목적이다.

## In / Out

| 기능 | 구분 | 검증 가설 | 이유 |
|---|---|---|---|
| 게시판 2곳 공지 수집 | In | H5 | 플러그인 구조로 게시판 추가가 쉬운지 확인 |
| 키워드·제외 키워드 매칭 | In | H3 | 첫 구독이 3분 안에 끝나는지 확인 |
| 마감일 추출 | In | H2 | 가장 위험한 가설. 정확도를 숫자로 확인 |
| `.ics` 캘린더 구독 링크 | In | H1 | 사람들이 캘린더로 받고 싶어 하는지 확인 |
| D-3, D-1 리마인드 | In | H4 | 리마인드가 신청 행동을 늘리는지 확인 |
| 이메일 알림 발송 | Out | - | `.ics` 링크로 H1 을 먼저 검증할 수 있어 서버 비용이 없다 |
| 웹 푸시 알림 | Out | - | 어떤 가설도 검증하지 않음 |
| 회원가입·로그인 | Out | - | 처음 10명은 링크 하나로 충분. 필요해지는 시점은 MS2 이후 |
| 게시판 5곳 이상 확장 | Out | - | H5 는 3곳 추가로 충분히 확인 가능 |

## 성공 기준

MS1 종료 시점에 아래를 **모두** 만족하면 MVP 는 성공이다.

- 마감일 추출 정확도 **90% 이상** (실제 공지 15건 이상)
- 인터뷰 10명 중 **4명 이상**이 최근 한 학기에 마감을 놓친 경험이 있고, 구독 링크 클릭률이 **30% 이상**
- 처음 10명 중 **5명 이상**이 `.ics` 링크를 캘린더에 실제로 추가

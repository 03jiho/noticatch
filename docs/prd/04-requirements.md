## 1. 사용자 스토리

| ID | 스토리 | 수용 기준 | 검증 가설 |
|---|---|---|---|
| US1 | 재학생으로서 관심 키워드를 1~3개 등록하고 싶다, 그래야 나와 상관없는 공지를 보지 않는다 | Given 처음 방문한 사용자가 When 키워드 3개를 입력하면 Then 180초 안에 구독 링크가 발급된다 | H5 |
| US2 | 재학생으로서 구독한 공지의 마감일이 내 캘린더에 들어오길 원한다, 그래야 직접 옮기지 않는다 | Given 마감일이 적힌 새 공지가 수집되면 When 캘린더를 새로고침하면 Then 일정 설명에 추출한 후보 마감일과 원문 줄이 함께 보이고, 후보는 "확인 필요"로 표시된다 (Cycle 1, P1) | H1, H2 |
| US3 | 재학생으로서 마감 3일 전과 1일 전에 알림을 받고 싶다, 그래야 신청을 잊지 않는다 | Given 마감이 3일 남은 구독 공지가 있으면 When 하루 한 번 실행이 돌면 Then D-3 알림이 한 번만 나간다 | H3 |
| US4 | 운영자로서 추출 결과를 원문과 대조해 확인하고 싶다, 그래야 틀린 마감일이 나가지 않는다 | Given 추출된 마감일이 있으면 When 검수 목록을 열면 Then 원문 줄과 추출 날짜가 나란히 보인다 | H2 |

## 2. 기능 요구사항

| ID | 요구사항 | 관련 스토리 | 우선순위 |
|---|---|---|---|
| FR1 | 게시판 2곳의 공지를 30분마다 수집한다 | US2 | Must |
| FR2 | 키워드·제외 키워드로 공지를 걸러 낸다 | US1 | Must |
| FR3 | 공지 본문에서 마감일 후보를 추출하고 못 찾으면 비워 둔다(추측하지 않는다) | US2, US4 | Must |
| FR4 | 구독별 `.ics` 피드를 발급한다 (무작위 토큰 URL) | US1, US2 | Must |
| FR5 | D-3, D-1 리마인드를 중복 없이 보낸다 | US3 | Must |
| FR6 | 구독 클릭·완료와 캘린더 추가를 기록한다 | US1 | Must |
| FR7 | 캘린더 일정 설명에 후보 마감일, 원문 줄, 원문 링크를 함께 넣는다 (P1) | US2 | Must |

## 3. 비기능 요구사항

| 영역 | 요구사항 |
|---|---|
| 성능 | 구독 링크 발급 응답 2초 이내 |
| 보안·개인정보 | 이메일·이름을 수집하지 않는다(무작위 토큰만). 삭제 요청은 24시간 안에 처리 |
| 접근성 | 키보드만으로 구독 완료 가능, 색에만 의존하지 않는 표시 |
| 분석 이벤트 | 아래 표 — `05-metrics.md` §4와 이름 일치 |

| 이벤트 이름 | 발생 시점 | 속성 |
|---|---|---|
| `landing_view` | 랜딩 페이지 진입 | 유입 채널 |
| `subscribe_click` | 구독 링크 버튼 클릭 | 유입 채널 |
| `subscribe_complete` | 구독 링크 발급 완료 | 키워드 수, 소요 초 |
| `ics_added` | 캘린더 피드가 처음 조회됨 | 캘린더 앱 종류 |
| `reminder_sent` | D-3 또는 D-1 알림 발송 | 단계(D3/D1) |
| `deadline_corrected` | 검수에서 추출 마감일을 고침 | 공지 ID |

## 4. 우선순위 (MoSCoW)

| 등급 | 항목 |
|---|---|
| Must | 게시판 2곳 수집, 키워드 매칭, 마감일 후보 추출, 후보·원문 병기 표시, `.ics` 구독 링크, D-3·D-1 리마인드, 구독 이벤트 기록 (= 03의 In) |
| Should | 검수 목록 화면 (MS1 후보) |
| Could | 제외 키워드 추천 |
| Won't (이번 범위) | 이메일 알림, 웹 푸시, 회원가입·로그인, 게시판 5곳 이상 (= 03의 Out) |

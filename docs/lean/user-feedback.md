# 사용자 시나리오와 페르소나 피드백 (10명)

> **이 피드백은 LLM(Claude)이 각 페르소나 역할을 맡아 작성한 가상 사용자 응답입니다. 실제 사람의 응답이 아닙니다.**
> 과제 조건(LLM 으로 서로 다른 페르소나 10명)에 맞춰 만들었고, 실제 재학생 인터뷰(README 1장의 검증 계획)를 대체하지 않습니다.

## 방법

1. 서로 겹치지 않는 페르소나 10명을 정한다 (학년, 직무, 기기, 기술 숙련도, 목표, 불편이 다름). 원본: [`experiments/personas.json`](../../experiments/personas.json)
2. 페르소나마다 **시나리오 1개**를 정하고, 그 시나리오를 **실행 가능한 테스트 코드**로 옮긴다. ([`tests/test_persona_scenarios.py`](../../tests/test_persona_scenarios.py), 10명 모두)
3. 테스트를 돌려 제품이 시나리오를 지키는지 평가한다. 실패는 백로그가 된다.
4. 각 페르소나가 쓴 시나리오 결과를 보고 남기는 피드백(점수, 한마디, 바라는 점)을 정리한다.

## 시나리오 코드가 찾은 실제 결함

페르소나 p07(오태양)의 시나리오 `test_p07_deadline_written_as_month_dot_day_with_weekday` 가 처음에 **실패**했다. 마감일이 `11.30(일)~12.5(금)` 처럼 적힌 공지를 제품이 읽지 못했다.

- 🔴 Red: [`46c3577`](https://github.com/03jiho/noticatch/commit/46c3577) 실패하는 시나리오 테스트
- 🟢 Green: [`f8991e4`](https://github.com/03jiho/noticatch/commit/f8991e4) 요일 괄호가 붙은 `M.D` 표기를 지원 (`3.5점` 같은 소수는 날짜로 안 봄)

## 한계

- 피드백과 점수는 모델이 상상한 것이라 실제 사용자와 다를 수 있다. 특히 "만족도 4.0" 같은 값은 제품 평가로 쓰면 안 된다.
- 시나리오 테스트는 제품 코드의 정확성은 검증하지만, 사용자가 화면을 보고 느끼는 불편은 검증하지 못한다.
